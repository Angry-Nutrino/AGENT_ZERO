### Q01 [CHAT] — What is the difference between a monolithic and a microservices architecture? What are the main tradeoffs? Answer from your training knowledge.

Monolithic architecture runs the entire application as a single, unified codebase and process. Microservices splits the system into independently deployable services that communicate over a network, each owning its own data and domain.

**Monolith tradeoffs:**
- Simple to develop, test, deploy, and debug initially
- Network calls are in-process — no latency, no serialization overhead
- Single codebase means tight coupling as it grows; a change in one place can break something unrelated
- Scales vertically only unless you clone the entire monolith
- Deployment is all-or-nothing; one bad module brings down everything
- Team coordination overhead grows superlinearly with codebase size

**Microservices tradeoffs:**
- Independent deployability — each service can be updated, scaled, and failed independently
- Technology heterogeneity — pick the right tool per service
- Organizational alignment — teams own services, not layers
- Network latency, serialization overhead, partial failure handling
- Distributed transactions are hard — eventual consistency becomes the default
- Operational complexity — monitoring, tracing, service discovery, deployment pipelines all multiply
- Testing across service boundaries is costly and flaky

The inflection point: when the monolith's deployment velocity drops below what the business needs, or when team coordination overhead exceeds the cost of distributed systems complexity. For most systems below ~5-10 developers and ~100k LOC, a well-structured monolith is the correct choice — the microservices tax isn't worth it until the scaling pressure is real.

### Q10 [CHAT] — What is the difference between symmetric and asymmetric encryption? When is each typically used? Answer from your training knowledge.

Symmetric encryption uses a single shared key for both encryption and decryption — fast, efficient for bulk data. Asymmetric encryption uses a public-private key pair, where one key encrypts and the other decrypts, with a significant computational cost.

Symmetric is typically used for encrypting data at rest (disk encryption, database columns) and bulk data in transit (TLS session encryption after the handshake). Asymmetric is used for key exchange (Diffie-Hellman, RSA), digital signatures, and identity verification — situations where two parties can't have pre-shared a secret. Real-world systems combine both: asymmetric to establish a shared session key, then symmetric for the actual data stream.

### Q15 [CHAT] — Explain how Python's asyncio event loop runs many coroutines on a single thread, and what happens to the whole loop if one coroutine performs a long blocking CPU-bound computation. Answer from your training knowledge.

The event loop runs on a single thread by cooperative multitasking: at each `await` point, the coroutine yields control back to the loop, which then switches to the next ready coroutine from its runnable queue. The loop uses `select`/`epoll` (or `IOCP` on Windows) to handle I/O readiness — when a socket has data or a timer fires, the corresponding coroutine is rescheduled. No preemption happens; a coroutine keeps the thread until it explicitly yields via `await`.

If one coroutine performs a long CPU-bound computation without yielding — pure Python arithmetic, loops, matrix ops — the entire event loop freezes for the duration. No I/O gets processed, no other coroutines run, no timers fire, no WebSocket heartbeats arrive. `asyncio.sleep(0)` calls inside the computation are the fix (yield periodically), but for genuine CPU-bound work the correct solution is `loop.run_in_executor(None, heavy_func)` which offloads it to a thread pool, keeping the event loop responsive.
