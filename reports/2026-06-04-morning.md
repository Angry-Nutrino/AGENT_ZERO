### Q01 [CHAT] — What is the difference between a monolithic and a microservices architecture? What are the main tradeoffs? Answer from your training knowledge.

Monolithic architecture packages everything into a single deployable unit — one codebase, one process, one database. Microservices decompose the system into independently deployable services, each with its own data store, communicating over a network.

**Tradeoff table:**

| Axis | Monolithic | Microservices |
|------|------------|---------------|
| Development velocity | Fast early, slows as codebase grows | Slower initial setup, sustained velocity per team |
| Testing | Simple integration tests | Complex — each service must be tested in isolation *and* in concert |
| Deployment | One deploy, all-or-nothing | Independent deploys per service |
| Scaling | Scale the whole application | Scale only the services that need it |
| Fault isolation | A crash in one module takes everything down | A crash in one service is contained |
| Operational complexity | One process, one log, one deploy pipeline | n processes, n logs, n pipelines, service mesh |
| Data consistency | Single ACID transaction | Distributed transactions (Sagas, eventual consistency) |
| Team autonomy | Tight coupling between teams | Each team owns its service end-to-end |
| Refactoring cost | High — changes ripple across the entire codebase | Lower per-service, but cross-service contract changes are painful |
| Startup cost | Low — one codebase, one DB, no network orchestration | High — CI/CD, service discovery, API gateways, container orchestration |
| Debugging | Single code path, single log stream | Trace across services, correlated logs, distributed tracing tooling required |
| Optimal team size | <10 developers | 5–9 per service, requires organizational buy-in |

**The decision rule:**

Start monolithic. Only decompose when a concrete constraint forces it — an independent scaling requirement, a team boundary that cannot be bridged by code review, or a technology requirement that cannot be satisfied in the current stack. Premature microservices multiply complexity without delivering the benefit.

### Q10 [CHAT] — What is the difference between symmetric and asymmetric encryption? When is each typically used? Answer from your training knowledge.

Symmetric encryption uses one shared key for both encryption and decryption — fast, efficient, suited for bulk data. Asymmetric encryption uses a public/private key pair: one encrypts, the other decrypts — slower, computationally heavier, but solves the key distribution problem.

Symmetric is used for encrypting files, disk volumes, database columns, VPN tunnels, and TLS session payloads (after the handshake). Asymmetric is used for key exchange (Diffie-Hellman, RSA), digital signatures, certificate-based authentication (TLS handshake, SSH, PGP), and any scenario where parties have never shared a secret beforehand.

Real-world systems use hybrid: asymmetric to exchange a session key, then symmetric for the actual encryption. TLS, Signal, PGP, SSH — all follow this pattern.

### Q15 [CHAT] — Explain how Python's asyncio event loop runs many coroutines on a single thread, and what happens to the whole loop if one coroutine performs a long blocking CPU-bound computation. Answer from your training knowledge.

Single-threaded cooperative multitasking. One event loop, one thread. A coroutine yields control at each `await` point — the loop grabs the yielded coroutine, schedules it, and resumes another. Multiple coroutines interleave on the single thread via these suspension points.

If one coroutine runs a CPU-bound computation — a tight loop, a heavy `sum()`, a `pandas` join, anything that doesn't `await` — it never yields. The loop can't preempt it. No other coroutine runs, no new connections are accepted, no timers fire. The entire application freezes until that computation completes.

The fix: `loop.run_in_executor(None, blocking_fn)` hands the CPU work to a thread pool. The coroutine `await`s the returned future, the event loop stays responsive on the main thread, and the expensive computation runs in the background without blocking anything else.
