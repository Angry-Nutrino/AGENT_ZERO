### Q05 [CHAT] — What is the difference between an asyncio.Lock and a threading.Lock in Python? When would you use each? Answer from your training knowledge.

An `asyncio.Lock` is a coroutine-based lock for single-threaded concurrent code — you `await lock.acquire()` and it suspends the current coroutine, not the thread. A `threading.Lock` is a preemptive OS-level lock for multi-threaded code — you call `lock.acquire()` and it blocks the calling thread entirely until released.

Use `asyncio.Lock` when you're inside async functions managing shared state across coroutines on the same event loop (e.g., serializing MiniLM `encode` calls from the main async thread and a background memorization task). Use `threading.Lock` when you have actual OS threads sharing state — like the vault dedup lock in memorization that guards against concurrent `memorize_episode` writes from different requests handled by different threads.

They are **not interchangeable**. Applying the wrong one either deadlocks your event loop (threading.Lock in an async context with `run_in_executor`) or silently fails to protect state across threads (asyncio.Lock doesn't serialize threads, only coroutines).

### Q08 [CHAT] — What is the CAP theorem? Name the three properties and explain what the theorem actually states about distributed systems. Answer from your training knowledge.

The CAP theorem states that in a distributed data system, you can guarantee at most two of three properties simultaneously:

**Consistency** — Every read receives the most recent write or an error. All nodes see the same data at the same time.

**Availability** — Every request receives a (non-error) response, without guarantee that it contains the most recent write. The system remains operational.

**Partition Tolerance** — The system continues to function despite arbitrary message loss or failure between nodes. This is non-negotiable in distributed systems — network partitions happen.

The theorem's actual claim: during a network partition, you must choose between Consistency and Availability. You cannot have both across the partition. CP systems (like HBase) will reject writes or return errors to preserve consistency. AP systems (like Cassandra) will accept writes and serve stale reads to stay available.

Outside of partitions, both C and A can be satisfied simultaneously. The theorem only forces a tradeoff *when* the network fails — which is why partition tolerance is the one property you cannot opt out of.
