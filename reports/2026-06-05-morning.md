Already answered this in exhaustive detail on 2026-06-02 (trained) and again on 2026-06-04 (re-verified). Nothing's changed.

The short version: monolithic starts simple — single deployable, shared memory, no network hops. Microservices decompose by bounded context — each service owns its data and communicates over HTTP/messaging.

**Tradeoff summary:**

| Axis | Monolithic | Microservices |
|------|------------|---------------|
| Dev velocity | Fast initially, slows as codebase grows | Slow initially, sustained at scale |
| Testing | Single process, easy integration tests | Requires contract tests, service stubs |
| Deploy | One artifact | N artifacts, coordination needed |
| Scale | Vertical only | Per-service horizontal |
| Fault isolation | One crash kills everything | Blast radius contained |
| Ops complexity | Low | High — observability, service mesh, config management |
| Data consistency | ACID trivially | Eventual consistency, sagas |
| Team autonomy | Low — coordination on every change | High — each team owns services end-to-end |

**The decision rule, unchanged:** start monolithic. Decompose only when a concrete constraint forces it — a team that can't move without stepping on each other, a service that needs different scaling than the rest, a deployment cycle that's too slow for one component. Premature decomposition is the more expensive mistake.

### Q10 [CHAT] — What is the difference between symmetric and asymmetric encryption? When is each typically used? Answer from your training knowledge.

Symmetric encryption uses a single shared key for both encryption and decryption — fast, efficient, and suitable for bulk data. Asymmetric encryption uses a public-private key pair, where the public key encrypts and the private key decrypts — slower but eliminates the key distribution problem.

Symmetric is typically used for encrypting large volumes of data (disk encryption, database encryption, VPN tunnels). Asymmetric is used for key exchange (Diffie-Hellman), digital signatures, and authentication (TLS handshakes). Real-world systems combine both: asymmetric to exchange a session key, then symmetric for the actual data payload.

### Q15 [CHAT] — Explain how Python's asyncio event loop runs many coroutines on a single thread, and what happens to the whole loop if one coroutine performs a long blocking CPU-bound computation. Answer from your training knowledge.

Python's asyncio event loop runs on a single thread using cooperative multitasking: it maintains a queue of tasks, and at each turn of the loop it polls a selector for I/O readiness, then resumes whichever awaitable is ready. `await` is a yield point — the coroutine voluntarily suspends, returning control to the loop's scheduler, which picks the next ready task. No parallelism, just interleaving at explicit suspension points.

If a coroutine performs a long blocking CPU-bound computation — say a tight loop with no `await` — it never yields, so the event loop can't schedule anything else until that call returns. The entire loop freezes: other coroutines starve, new connections queue, timers fire late, and the process appears hung. The correct fix is `loop.run_in_executor(None, blocking_fn)` which offloads the work to a thread pool, letting the coroutine `await` the result without blocking the loop.
